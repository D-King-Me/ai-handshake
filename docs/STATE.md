# 四态两比特

这个仓库里"握手"返回的不是 `True/False`，是两个比特。

## 为什么不返回布尔

布尔只有对错，没有"还不确定"和"不必再问"。

- 一次 `False` 可能是网络抖动（重试就有），也可能是没钥匙（重试一万次也没有）。把这两种混成一个 `False`，调用方只能瞎猜要不要再试。
- 更贵的问题：一个明确不通的供应商，如果每次链路轮转都去问一遍，你付的是**每次都失败的那笔延迟**，而不是算力。

## 四位怎么分

| 位 | 名字 | 判据 | 处置 |
|---|---|---|---|
| `01` | 通 | 有回复且耗时 ≤ 慢阈值 | 进候选，正常用 |
| `10` | 慢 | 有回复但超过慢阈值 | 降级，排在后面 |
| `00` | 不确定 | 超时、429 限流、空回复、5xx | 重试一次；仍不定则换下一家 |
| `11` | 隔离 | 401/403/404、连不上、缺钥匙、缺模型名 | 排除，不再发起请求 |

慢阈值默认 8000ms，改 `base.py` 里的 `SLOW_MS`。

## 关键在"隔离"这一位

`11` 不是"这次失败"，是"**在条件改变前不必再问**"。

这意味着：

1. 判定一次，后续轮转直接跳过；
2. 想恢复，只改一个条件（补钥匙、起服务、换地址），下一次握手自动回到 `01`；
3. 任何"到底哪家能用"的结论，都是可复核的状态，而不是一段记忆。

## 和调用方的关系

调用方只做一件事：**读状态位，挑第一个 `01`**。

```python
for a in adapters:
    if a.ping()["state"] == "01":
        return a
```

被 `11` 的连 `chat()` 都没进过 —— 快不是因为算得快，是因为**没算**。
